2.3 - Loop Unrolling on Y-axis (optim2)

genevievec@az4-a7900-2:~/easypap-se$ ./run -n -k blur --load-image images/1024.png -i 100 -v seq -wt optim2 --show-hash
Using kernel [blur], variant [seq], tiling [optim2]
Computation completed after 100 iterations
5182.366
SHA256 key stored in data/hash/blur-seq-optim2-dim-1024-iter-100-arg-none.sha256


Observation: Unrolling the y-axis loop unexpectedly increased the execution time (from ~5114ms to ~5182ms).
Explanation: While unrolling removes the small overhead of loop counting, it exposes a much larger bottleneck. To process a single pixel's 3x3 neighborhood, the code makes 37 separate function calls (9 pixels × 4 color extractions, plus 1 final color pack). Because the code is compiled with -O0 (no compiler optimisations), these functions are not automatically inlined. The heavy CPU cost of jumping back and forth in memory for 37 function calls per pixel completely outweighs the tiny amount of time saved by deleting the yloc loop.
